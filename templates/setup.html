Two ways in: open an existing app (fastest if you already see Default Application), or create a new one. Both end at the same place — a Client ID and Secret on the app's page.

Shortest path — use an existing app

  1. Open Apps & Credentials.

    You should be on the page headed “You’re in sandbox mode.” If you see a banner asking you to upgrade to view live credentials, ignore it — sandbox is what you want.

    Open Apps & Credentials → 

    {{ dashboard_url }}
  2. Under “REST API apps”, click an existing app name.

    Most sandbox accounts already have one called Default Application. Its Client ID and Secret are shown on the app's own page. Skip to step 4.

Or create a new app

  1. Click “Create App” and fill the dialog.

    The dialog has exactly three fields. Here is what each one means:

    App Name Any label you recognise later. Suggestions: paypal-saas-mvp or the brand name you set above. It has no effect on the API.
    Type

    Choose Merchant — “Accept payments as a merchant (seller)”. Your app is a single seller taking its own payments, which is exactly this case.

    Do not choose Platform. Platform is for marketplaces and partner onboarding — it creates a special partner account and grants scopes this app does not use. PayPal's own docs say: “For Embedded integration, select Merchant.”
    Sandbox Account

    The business sandbox account that the REST credentials act on behalf of — the “seller” in every test transaction. PayPal creates one for you and pre-selects it, usually looking like sb-xxxx@business.example.com (US). Keep the default.

    If the dropdown is empty, you have no business sandbox account yet. Create one first:

    Open Sandbox Accounts →

    On that page: Create Account → Business → accept the defaults → Create. Then return to Apps & Credentials and re-open the Create App dialog.

    Click Create App at the bottom of the dialog.

  2. Copy the Client ID and Secret from the new row.

    The app appears under “REST API apps”. The Client ID is visible in the row; the Secret is masked with dots and has a copy icon next to it. If you lose the Secret, use the app's page to regenerate it.

    Do not share these. PayPal's own banner on that page says: “Store credentials safely, and never share client IDs or secrets publicly.” The form below writes them to config/secrets.json with mode 0600.

  3. Paste into the form below and save.

    The app calls PayPal OAuth once to validate. A bad Client ID or Secret is rejected before anything is written.

Webhook ID — a separate, later step

The Client ID and Secret are enough to create subscriptions. To receive lifecycle events you also need a Webhook ID, which lives on a different part of the same app page:

  1. Open your REST app (the same app name from step 2 or 3).
  2. Find the Webhooks section on that app's page and click Add Webhook.
  3. URL: {{ cfg.BASE_URL }}/webhook — it must be public HTTPS, so run ngrok first (see below).
  4. Tick BILLING.SUBSCRIPTION.ACTIVATED, BILLING.SUBSCRIPTION.CANCELLED, BILLING.SUBSCRIPTION.EXPIRED, and PAYMENT.SALE.COMPLETED.
  5. Save, then copy the Webhook ID (starts with WH-) into the field below.

Not the NVP/SOAP section. On the Apps & Credentials page there is also a section headed “NVP/SOAP API apps — Setup and manage webhooks for NVP/SOAP APIs.” That configures the legacy SOAP webhooks. This app uses the REST API; its webhooks are on the REST app's own page, not there.

Public HTTPS URL for the webhook

PayPal cannot reach localhost. Expose the app first, then paste the public URL into BASE_URL in .env and into the webhook URL above: 

# Claim a free static domain at https://dashboard.ngrok.com/cloud-edge/domains
ngrok http --domain=your-static-name.ngrok-free.app 5000

Common confusions

“Upgrade your account to PayPal for Business to view live credentials” Ignore. That banner is about live credentials. Sandbox credentials are what this app needs.
“Our dashboard works best on desktop” Cosmetic. The Create App dialog works on mobile, but copy-paste of the Secret is easier on desktop.
I see two credential rows, one masked That is the existing app's Client ID (visible) and Secret (masked). Both belong to the same app.
I see no “Create App” button You are on the Live tab, not Sandbox. Look for the “You’re in sandbox mode” banner at the top of Apps & Credentials.
